Zcash activates NU7 with 25-second block targets

Zcash activated NU7 at block 3,543,405, cutting target block spacing to 25 seconds while adding shielded-action limits and changing how fees support miners.

The Finality DeskNov 7, 2026 · 14:24 UTC3 min read#d87bd3

Zcash activated its NU7 mainnet upgrade at block 3,543,405, reducing the target interval between blocks from 75 seconds to 25 and lowering the expected wait for a payment confirmation. The CoinDesk report on the activation says the block was mined at 02:34 UTC on Nov. 6. The upgrade changes consensus rules for block timing, shielded activity, transaction validity and fee handling.

The 25-second target comes from ZIP 218. It does not guarantee that every payment becomes usable in 25 seconds: block production varies, and exchanges and other services choose their own confirmation requirements. CoinDesk reported that the 225 blocks after activation averaged about 39 seconds as mining difficulty adjusted toward the new target.

How does NU7 increase shielded payment capacity?

ZIP 218 pairs shorter target spacing with per-pool and global limits on shielded actions in each block. Those limits bound the validation and synchronization work that more frequent blocks could otherwise impose on nodes and light wallets.

The Zcash Foundation’s Zebra 7.0.0 release notes say the limits more than double Orchard throughput, from 2.9 to 6.6 transactions per second, while cutting worst-case sync bandwidth that a spammer could impose on light wallets by about 37%. Zebra applies the limits both when it builds block templates and when it admits transactions to its mempool, rejecting oversized activity before it reaches a block.

The faster target also changes issuance timing. ZIP 218 divides block rewards by three and triples the number of blocks between halvings, keeping the amount of ZEC issued per day and the four-year halving schedule unchanged. The upgrade does not raise Zcash’s 21 million ZEC supply cap.

How does NU7 change fees and future block rewards?

NU7 activates the Network Sustainability Mechanism through ZIP 235 and ZIP 237. Miners keep 40% of each block’s transaction fees; the remaining 60% is removed from circulation and recorded in a public reserve. Starting at mainnet height 8,939,664, blocks can reissue a predictable portion of that reserve on top of their regular subsidy.

The reserve is intended to contribute to future block rewards as scheduled subsidies decline. The upgrade specification says the mechanism does not increase the supply cap: reissued funds were previously removed from circulation or left unclaimed by miners. The schedule sets the reissuance height; it does not mean miners receive the reserved fees immediately at NU7 activation.

Which transactions and nodes are affected by activation?

NU7 makes every version 4 transaction invalid, while versions 5 and 6 remain valid. That rule applies to transparent-only and Sapling transactions as well as Sprout transfers. Because Sprout transfers can only use version 4, ZEC left in the Sprout pool became unspendable at activation. CoinDesk reported about 12,224 ZEC remained there.

Wallets and transaction services must stop constructing version 4 transactions for post-activation inclusion. Re-signing an invalid version 4 transaction cannot make it valid; a non-Sprout payment may instead be recreated in a supported format. Sprout has no supported post-activation replacement format.

Node operators also had to install NU7-compatible software before activation. The Foundation’s release notes warn that after the height, NU7 nodes disconnect peers running older versions, and unupgraded nodes follow a different chain. The activation therefore changed which consensus rules mainnet nodes enforce, as well as the expected pace and capacity of shielded payments.
