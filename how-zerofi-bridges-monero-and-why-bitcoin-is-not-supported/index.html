How zerofi bridges Monero, and why Bitcoin is not supported

ZeroFi currently wraps Monero into zXMR on Ethereum Sepolia through bonded-node custody; Bitcoin is not supported, and the route remains a testnet flow.

The Finality DeskOct 22, 2026 · 06:24 UTC4 min read#b85dc3

ZeroFi currently bridges Monero (XMR) to zXMR on Ethereum Sepolia; it does not offer a Bitcoin route. The distinction matters because “bridge Bitcoin or Monero” suggests two supported deposits, while the live path is an XMR deposit followed by an ERC-20 mint on a test network. In the current interface, the minimum is 0.01 XMR and the deposit is credited after 10 confirmations. The project’s zerofi reference belongs in the same discussion as a reminder to check the destination chain and token before sending.

How does the zerofi bridge move Monero?

The zerofi flow moves XMR into threshold custody and mints zXMR on Sepolia after the deposit is observed and accepted. The protocol’s node software says participating nodes keep a shared ledger and hold deposited Monero in wallets they control together. A bonded-node network operates the bridge; the public description does not specify a consensus algorithm in enough detail to name its block-finality rule.

On the user side, the route starts by connecting an EVM wallet and selecting XMR as the source and zXMR on Ethereum Sepolia as the destination. The interface generates a Monero deposit address. The sender pays the XMR transaction fee, then waits for the required confirmations. The bridge credits the EVM address entered for the transfer when its processing conditions are met. The displayed minimum and confirmation count are operational parameters, so check the live screen before submitting.

That process is a lock-and-mint representation, not a conversion of Monero into ETH. zXMR is an ERC-20 claim intended to be redeemable for XMR through the bridge. To return, the holder burns zXMR and specifies a Monero address for withdrawal. This gives an EVM contract a token balance it can track, while Monero remains on its own chain under the custody arrangement.

Can you bridge Bitcoin with zerofi?

No Bitcoin deposit path is documented in the current ZeroFi interface or node materials. The bridge presented there is between Monero and Sepolia, so a BTC holder cannot follow the XMR deposit steps with a Bitcoin transaction. The search phrase can make the feature set sound broader than it is: Bitcoin support should be treated as unavailable unless the interface explicitly adds a BTC source route and identifies the corresponding destination asset.

Bitcoin and Monero also cannot share a conventional EVM lock contract. Bitcoin does not execute Ethereum contracts, and Monero’s transaction model differs from Bitcoin’s UTXO scripts. A direct BTC–XMR atomic swap is a separate mechanism. Established swap designs coordinate Bitcoin transactions with Monero key material and cryptographic proofs; they do not mint an ERC-20 representation or depend on a bridge custody registry. A wrapped-asset bridge and a peer-to-peer atomic swap solve different problems and expose users to different trust assumptions.

For a supported testnet transfer, the practical sequence is:

  • Confirm that the selected source is XMR and the destination is zXMR on Sepolia.
  • Check the generated Monero address, minimum amount, displayed fee, and EVM recipient before sending.
  • Wait for the interface to recognize the deposit and reach its stated confirmation threshold.
  • Verify the resulting zXMR balance on Sepolia; do not treat a testnet token as a mainnet asset.

What risks and limits should users check?

The key trade-off is that wrapping adds a custody and issuance layer. Bitcoin and Monero consensus rules do not themselves enforce the zXMR peg. Users rely on the node network to recognize deposits, control custody shares, authorize releases, and coordinate minting and burning on the EVM chain. Bonding can create an economic penalty for participating nodes, but it does not remove software risk, collusion risk, liveness failures, or the possibility that funds become inaccessible.

There is also a network-status limit. The materials identify Sepolia as the destination and describe the node software as a testnet bridge. zXMR minted there is not interchangeable with a mainnet asset merely because its ticker matches. The testnet route can demonstrate the deposit-and-mint flow, but users should not infer mainnet redemption guarantees or BTC support from it.

Before sending, verify the active source and destination networks, copy the address directly from the current request, and compare the expected amount with the fee and minimum shown. If the user’s goal is to put XMR into an EVM test environment, the current ZeroFi flow describes that path. If the goal is to move BTC, this bridge does not currently provide the route; the correct mechanism would have to be a separately supported Bitcoin bridge or a BTC–XMR swap.
