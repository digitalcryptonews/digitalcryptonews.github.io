Berachain bridge tokens missing: delivery may be complete

Berachain bridge tokens not showing in wallet? They usually arrived; check Berascan, then switch to Berachain, import the token, or refresh your RPC.

The Finality DeskNov 27, 2026 · 11:41 UTC5 min read#53b67f

Berachain bridge tokens usually arrive when Berascan shows the destination transfer, even if the wallet balance is blank.

A wallet reads balances for its selected network through that network’s RPC endpoint, then displays tokens it knows how to query. The Berachain bridge at berachainbridge.app helps explain how assets move across chains; for a missing balance, the destination record is the useful starting point.

Check Berascan for the destination transfer

Berascan can show whether the bridged asset reached your Berachain address. Search your receiving address on a Berachain explorer and inspect its token balances and transaction activity.

Look for the destination-side transaction and the token transfer to your address. A confirmed transaction on the source chain only establishes that the source action completed. The destination record tells you whether the asset was delivered on Berachain.

If the token appears in the explorer’s token balances, delivery worked. The remaining problem is how the wallet reads or displays that balance. Note the token contract address shown for that asset; you will use it if the wallet needs the token imported.

If you are moving from Ethereum, for instance, the bridge from Ethereum to Berachain involves activity on both chains. Check the Berachain destination address, not just the Ethereum transaction. A balance there can confirm delivery even while MetaMask still shows zero.

Switch the wallet to Berachain and add the token

MetaMask must be connected to Berachain to display a Berachain balance. Berachain mainnet uses chain ID 80094, and BERA is its gas token.

When the wallet is set to Ethereum or another network, it queries that network’s RPC. It will not display the balance held at the same address on Berachain. Select Berachain, then reload the wallet and check the account again.

If Berascan lists the asset but MetaMask still omits it, import the token using the contract address shown on the explorer. Token symbols such as USDC or HONEY are labels; the contract address identifies the token the wallet should query. Confirm that the explorer is showing the Berachain contract and that the address belongs to the token you expect.

Importing a token adds its balance to the wallet’s display; it does not move the asset. Use the contract address from the explorer’s token record, and check the token name and address before importing. A familiar symbol alone is not enough to identify a token safely.

Refresh a lagging Berachain RPC

A stale or rate-limited Berachain RPC can make a delivered token appear to have a zero balance. EVM wallets ask the selected network’s RPC for account and token data; they do not read balances from the bridge itself.

This gives you a useful comparison: Berascan shows the token at your address, but the wallet says zero. The explorer and wallet can differ because they query different RPC services, and a custom endpoint may be behind or unable to serve the wallet’s request promptly. The balance can be present on-chain while the wallet’s view remains stale.

To test this, change Berachain’s RPC URL in the wallet to another public Berachain RPC, then reload the account and token list. If the balance appears, the old endpoint was returning stale data. If it remains missing, compare the wallet’s selected address and network with the address and token record on Berascan.

Changing the RPC changes where the wallet fetches network data; it does not transfer the token or alter its contract. Keep the chain set to Berachain and use an endpoint intended for that network.

When to contact support

Contact the bridge’s support when the source transaction is confirmed but you cannot find a corresponding destination transfer on Berascan. Contact your wallet provider when Berascan shows the token at your address and the wallet still fails after you have checked the network, imported the verified contract, and refreshed the RPC.

Include the source transaction hash, receiving address, and destination explorer result so support can investigate the specific transfer or wallet display. Once the balance appears, confirm the account and token in MetaMask before using the asset; that leaves you with a visible Berachain balance you can act on.

Questions about missing Berachain bridge tokens

How long should I wait before a Berachain bridge transfer counts as stuck?

There is no single wait time that applies to every transfer. Check Berascan for a destination transaction: when it appears, delivery is recorded on Berachain, even if your wallet has not updated. If the source transaction is confirmed and no destination record appears, contact the bridge’s support with the transaction hash rather than judging by the wallet’s blank balance alone.

Is it safe to import a token contract I found on an explorer?

Import it only after confirming that the explorer is for Berachain and the contract record matches the token you intended to receive. A token symbol by itself is not a reliable identifier. The contract address is what the wallet uses to query that token’s balance.

Why did I receive a different token than the one I sent?

Tokens on the destination chain can have a different contract address or representation from the asset on the source chain. Compare the destination token’s contract and name with the transfer details, rather than relying on the ticker alone. If the destination record does not match what you expected, ask the bridge’s support to identify the asset tied to that transfer.
