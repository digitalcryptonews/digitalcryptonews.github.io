Zcash activates NU7, moving mainnet to 25-second blocks

Zcash activated NU7 at block 3,543,405, cutting target spacing to 25 seconds and changing subsidy, fee-reserve and transaction-validity rules.

The Finality DeskNov 9, 2026 · 05:52 UTC3 min read#aa4bb8

Zcash activated its NU7 network upgrade at mainnet block 3,543,405 on Nov. 5, cutting the target block interval from 75 seconds to 25 seconds and changing issuance, fee handling and transaction validity. The change applies through consensus rules: full nodes and miners that did not upgrade before activation can follow a different chain. The Block’s report on NU7’s activation gives the height and date.

The upgrade implements ZIP 218’s shorter block spacing. More frequent blocks shorten the expected wait for a first confirmation, but do not by themselves change how many confirmations a wallet or exchange requires before treating a payment as settled.

How does NU7 speed up blocks without speeding up issuance?

ZIP 218 reduces the per-block subsidy by a factor of three as the target interval falls from 75 seconds to 25. That keeps the rate of new ZEC issuance per unit of time essentially unchanged. To preserve the four-year halving cadence, NU7 also triples the number of blocks between halvings. The 21 million ZEC supply cap remains in place.

The change therefore increases the number of block events per hour while lowering the subsidy attached to each block. It is not a threefold increase in the scheduled rate of coin issuance. The Zcash Foundation’s Zebra 7.0.0 release notes describe the subsidy adjustment and the unchanged halving schedule.

What happens to transaction fees under the Network Sustainability Mechanism?

ZIP 235 removes 60% of each block’s transaction fees from circulation and places them in a reserve; miners receive the remaining 40%. ZIP 237 provides for part of that reserve to be reissued through future block rewards. The mainnet start point is block 8,939,664, expected in 2031, according to the release notes.

The reserve is intended to make part of the fee stream available for block rewards as ordinary block subsidies decline. The mechanism does not immediately pay the reserved portion to miners: at activation, miners claim only their 40% share of each block’s fees. Future reissuance follows a separate schedule from the halving interval.

Which transactions and nodes are affected by activation?

NU7 makes version 4 transactions invalid under the network rules. Sprout transfers can only use that version, so ZEC remaining in the original Sprout pool cannot be spent normally after activation. The Block reported about 12,224 ZEC in Sprout at the activation height.

Node operators needed NU7-compatible software before the activation height to remain on the consensus chain. The Foundation’s release notes say Zebra nodes disconnect peers running older versions after activation; nodes that have not upgraded follow a different chain. That makes NU7 a coordinated consensus change, not a wallet-only update.

The upgrade also sets per-block limits on Orchard, Ironwood and Sapling activity and disallows new Sprout JoinSplits. In Zebra, those limits apply when the node admits transactions to its mempool and when it builds block templates, so transactions exceeding the limits are rejected before block construction. The release notes say the Orchard limit change raises throughput from 2.9 to 6.6 transactions per second while reducing worst-case sync bandwidth pressure on light wallets. Those limits shape what blocks can contain; the shorter target interval changes how often the network aims to produce them.
